# АГЕНТСКИЕ ПРАВИЛА КОДА. НАРУШИЛ = ПЕРЕДЕЛАЛ С НУЛЯ.

Эталон — человеческий системный код, не энтерпрайз-каша из gpt3.5. Каждое правило проверяется по графу вызовов, git-истории и ассемблеру, а не на глаз.

## 1. ZERO-COPY НАМЕРТВО

- парсинг только по `&[u8]` и `&str` через simdutf8.
- `.clone()`, `.to_string()`, `.to_owned()`, `from_utf8_lossy().into_owned()`, `format!()` в hot path = профнепригодность. форматирование — только на границе сериализации ответа наружу.
- body страницы/скрипта: один `bytes::Bytes`, дальше `Bytes::slice()` — атомарный инкремент счётчика ссылок, ноль копий. `Bytes::copy_from_slice` допустим один раз на входе, если источник не в арене.
- `Cow<'a, str>` пока только читаешь — бесплатная ссылка. аллокация только при реальном изменении.
- CompactString допустим только для внешних границ (заголовки, url наружу). внутри пайплайна — срезы и id.

## 2. LOCK-FREE ИЛИ СМЕРТЬ

- `Arc<Mutex<T>>` исключён. `Arc<RwLock<T>>` исключён.
- передача данных между потоками — только каналы: crossbeam-channel (SPSC/MPSC) или rtrb.
- мапы — scc::HashMap (lock-free, уже в воркспейсе). вторую параллельную мапу (dashmap) не тащить — это дубль по правилу §5.
- счётчики — голые `AtomicU64`/`AtomicU32`, Ordering::Relaxed если не нужен happens-before.
- статистика: `#[repr(align(64))]` HotLine/ColdLine на атомарках. никакого serde_json::Value на каждый чих — счётчик инкрементится, сериализуется только при запросе /stats.

## 3. СТРУКТУРЫ ВМЕСТО КАШИ

- куки и любой поиск — строго O(1)/O(log n): HashMap/HashSet/BTreeSet с dedup. O(n²) перебор по Vec — ошибка.
- CookieJar: поиск по host+path — через хэш-ключ CompactString или дерево, не линейный скан.
- PRNG — ровно один `SplitMix64Rng`/`Identity` на контекст, гоняется по значению. зоопарки `thread_local!` с рнг запрещены.
- больше 3 аргументов у функции — собирай в структуру контекста (AssembleContext/VisitCtx-стиль). глушить `#[allow(clippy::too_many_arguments)]` запрещено.

## 4. ПАМЯТЬ И СТРОКИ

- scratch-память выделяется один раз и переиспользуется: `bumpalo::Bump` (уже в зависимостях), `BytesMut`, арены. пер-вызов `Vec::new()`/`String::new()` в цикле — дыра.
- длинные повторяющиеся строки (User-Agent, пути, имена методов, host) — строковый интернер на старте: маппишь в u32 и по пайплайну гоняешь 4-байтовый KeyId вместо байтовых срезов. `Vec` индексируется по KeyId, не `HashMap<(String, String)>`.
- финальный ответ собирается в один `BytesMut`/arena-буфер, сериализация one-shot. никаких промежуточных json-деревьев.

## 5. SSOT (закон единого источника правды)

- копипастить логику трансформаций, хэширования, парсинга байт, битовых сдвигов ЗАПРЕЩЕНО. вся математика и алгоритмы — строго в `core-utils::crypto` / `core-utils::math` / `core-utils::encoding` / `core-utils::rng`.
- внешний код (воркеры, солверы, парсеры) обязан импортировать и вызывать, а не реализовывать локальные копии. sha256/midstate/hmac — уже в core-utils::crypto, вторая реализация в крейте = провал аудита.
- операционный критерий: увидел одно и то же вычисление в третий раз — выносишь в core. на первом повторе абстракция обычно неправильная. можешь удалить одну копию и подставить вторую без потери корректности → дублирование, выносишь. не можешь (реально разные лимиты/ветки сериализации) → это две legit-реализации контракта, оставляешь с комментарием-различием.

## 6. МОНОЛИТНОСТЬ ДОМЕННЫХ МОДУЛЕЙ (анти-микрофайлы)

- запрещено плодить файлы по 10-50 строк на каждую утилиту. родственный функционал живёт в одном плотном по логике файле.
- extension-trait на примитивах (`impl BytesExt for [u8]`, `impl StrExt for str`) — правильный способ схлопнуть утилиты в SSOT: вызывающий дёргает `buf.rot_xor(0xdead)` без простыней импортов.
- если правится алгоритм/константа — правка строго в одном файле ядра, не размазывается диффами по десяти модулям.
- граф вызовов — звезда (одна функция в core, десятки вызовов), не лес (мини-модуль с копией на каждую фичу).
- именование: одна операция = одно имя везде. `hash_it`/`compute_digest`/`mix_bytes` для одного и того же = признак параллельных генераций, ошибка.

## 7. ИЗОЛЯЦИЯ ЯДРА

- core-utils не знает о доменных типах: никаких импортов session-state/payload-gen и т.д. зависимости строго в одну сторону: бизнес-логика -> core.

## 8. ПО КРЕМНИЮ

- структуры стейта — `#[repr(C, align(64))]`, кэш-линии не делятся между потоками (head/tail кольца — на РАЗНЫХ кэш-линиях, иначе false sharing).
- стейт хэш-алгоритма — голые u64/u128/`std::arch::x86_64::__m256i/__m512i` регистры. полный unroll через макросы (lz_batch16 уже так делает). компилятор держит стейт в регистрах, никаких промежуточных массивов.
- ветвления через cmov-стиль (`select`/тернарники), не через предсказуемый if по случайным данным.
- fixed-capacity: SmallVec с inline-ёмкостью вместо Vec::new в цикле.
- между потоками — SPSC кольцо: размер строго степень двойки (битовая маска `idx & (N-1)` вместо деления), head и tail — AtomicUsize на разных кэш-линиях, Acquire/Release. ни одного мьютекса.
- unsafe допустим только там, где проверяемо быстрее safe (copy_from_nonoverlapping по выровненным бланкам) и локален. каждый unsafe — обязан иметь инвариант, который соседний safe-код не ломает.

## 9. АНТИ-AI-КОД

- баг фиксится в одном месте. один и тот же баг в 3-4 местах = «оригинала не было, было 4 генерации» = провал.
- одинаковый паттерн в двух независимых местах — признак независимых генераций, а не рефакторинга. проверяй перед добавлением нового.
- никаких: мёртвого кода с видом защиты (catch_unwind при panic=abort), заглушек, TODO, фейковых тестов, `let _ = x;` на выброшенной константе, println-отладки.
- тесты — только проверяющие контракт (вход → выход, инвариант, граница), не пиннинг текста реализации.

## 10. СБОРКА

- компиляция только через zig (cargo-zigbuild, target x86_64-pc-windows-gnullvm / x86_64-unknown-linux-gnu). либы (ucrt, ole32, cfgmgr32, synchronization) зиг несёт свои.
- НЕ КОМПИЛИРОВАТЬ, пока владелец явно не сказал. сборка — привилегия человека, не агента.

## 11. ИЗВЕСТНЫЕ ЛОМКИ (чинить при любом касании)

- supervisor/src/fleet.rs `pump()`: глобальный таб-id считается как `local + lane`, а encode_tab делает `lane + local*N` — 7 из 8 лейнов теряют события намертво. slot_of — линейный поиск, заменить на хэшмапу hub_tab -> slot_idx.
- flow.rs nav-hop: Session::new с пустым jar теряет куки при каждом редиректе — jar обязан наследоваться.
- один canvas_seed рулит preset(CPU), skill и canvas-шум одновременно — корреляция палится. сид identity (proxy) стабильный, ASN-гео — отдельный слот Identity.
- reslot_for_asn пересчитывает preset → дрейф GPU/CPU с одного IP между сессиями. запрещено.
